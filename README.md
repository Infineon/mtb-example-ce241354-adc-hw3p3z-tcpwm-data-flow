# PSOC&trade; Control C3M/P8: ADC-HW3P3Z-TCPWM dedicated datapath

This code example applies for PSOC&trade; Control C3M/P8 MCUs. It demonstrates the dedicated datapath between ADC, hardware 3P3Z filter, and TCPWM. 

A TCPWM channel configured as PWM is used for triggering the conversion of the ADC channel on its terminal count. An ADC filter is enabled and bypassed all filters in it. It is required for the dedicated datapath to work. The output of the ADC filter is directly fed to the hardware 3P3Z filter. The output of the 3P3Z filter will be copied to the Compare 0 register of the TCPWM. All these data transfers will happen without the intervention of the CPU.

The CPU 0 in the PPCA subsystem reads the ADC output, ADC filter output, and HW3P3Z filter output in frequent intervals, and then sends it to the main CPU. The main CPU will print it on the UART console. 

The 3P3Z filter is configured in such a way that the duty cycle of the PWM output will be varied along with the ADC input voltage. The ADC input is from a potentiometer on the EVK. So that the user can see that the PWM pulse width is getting modulated when the potentiometer is rotated.

As the PWM output is connected to an LED on the evaluation kit (EVK) along with a GPIO on the header, you can monitor the LED brightness varying with the potentiometer.

## Design and implementation

This code example demonstrates the capabilities of the PSOC&trade; Control C3M/P8 MCU to transfer data between ADC, HW3P3Z filter, and TCPWM without the intervention of the CPU. This MCU has four different ADC groups. In this code example, the first channel from the first ADC group, the first channel from the second HW filter, and the first channel from the TCPWM 1 group 0 are used.

**Figure 2. Peripheral configuration**

![](images/peripheral-configuration.png)

**Figure 2** shows the peripheral configuration of the code example. The first channel from the ADC Group 0 is triggered through the EPU by the TCPWM[1].Group[0].Channel[0], which is configured in PWM mode. EPU Combiner 60 and EPU processing unit T1 0 are used for that. 

On completion of the conversion of the ADC, the converted data will be fed to the ADC Filter 0 in ADC Group 0. As all filters in this channel are bypassed, this module will move the data to the HW 3P3Z filter 0 in hardware filter 3P3Z Group 1. 

The HW3P3Z filter is configured to provide the required gain to the input to make it in the range of the TCPWM duty cycle. It will process the input data and move the data to the TCPWM Compare 0 register.

Along with these, the PPCA CPU 0 reads ADC output, ADC filter output, and HW3P3Z filter output in frequent intervals, and then shares it with the main CPU. The main CPU will send this data to the PC through the debug UART. **Figure 1** shows the debug UART capture.

**Figure 3** shows the timing of the peripheral activities in the code example. As shown in **Figure 3**, the PWM triggers the ADC conversion. When ADC conversion is completed, the ADC filter will process it and move the data to the HW3P3Z filter. Then the HW3P3Z filter processes the data and moves it to the Compare 0 register of the TCPWM configured as PWM. This new value will be reflected in the next cycle. Reading of the ADC result, the ADC filter output and HW3P3Z filter output by the PPCA CPU 0 are not in sync with the PWM, ADC, ADC filter, or HW3P3Z filter.

**Figure 3. Timing diagram**

![](images/timing-diagram.png)

**Figure 4** shows the relation between the ADC input from the potentiometer and the width of the PWM. When the potentiometer output goes up, the width of the pulse comes down and vice versa. The same signal is connected to LED D13 on the EVK. Observe that the LED brightness increases when the potentiometer is rotated in the clockwise direction, i.e. when the width of the PWM decreases. 

**Figure 4. PWM modulation with ADC input**

![](images/waveform.png)
